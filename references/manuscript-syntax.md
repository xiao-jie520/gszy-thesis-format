# 稿件语法

`build_thesis.py` 读一份 Markdown 稿件，输出规范 .docx。这里给出完整语法与一份可直接运行的示例。

## 1. frontmatter

文件开头用 `---` 包住，只放封面信息，键值都是纯文本：

```yaml
---
title: 基于Spring Boot的药房管理系统的设计与实现
title_en: Design and Implementation of a Pharmacy Management System Based on Spring Boot
advisor: 张三  教授
major: 医学信息工程
grade: 2022级
author: 李四
date: 二〇二六年六月
header: 甘肃中医药大学本科毕业论文（设计）
college: 医学信息工程学院
defense_date: 2026年5月20日
---
```

| 键 | 落到哪里 | 缺省 |
| --- | --- | --- |
| `title` | 封面标题、题目内页、目录；可用 `|` 指定换行位置 | 论文题目 |
| `title_en` | 内页英文题目 | 空 |
| `advisor` | 封面「指导教师姓名职称」 | 空 |
| `major` | 封面「专业名称」 | 医学信息工程 |
| `grade` | 封面「学生年级姓名」前半 | 空 |
| `author` | 封面「学生年级姓名」后半 | 空 |
| `date` | 封面底部、内页底部 | 二〇二六年六月 |
| `defense_date` | 封面「论文答辩日期」 | `    年    月    日` |
| `college` | 封面与内页首行学院名 | 医学信息工程学院 |
| `header` | 页眉文字 | 甘肃中医药大学本科毕业论文（设计） |

## 2. 标题

```markdown
# 摘　　要
# Abstract
# 第1章 引言
## 1.1 研究背景与意义
### 1.1.1 三级标题
# 第2章 关键技术
# 总　　结
# 致　　谢
# 参考文献
# 附　　录
### 附录A 核心代码
```

- `#` → 一级标题，`##` → 二级，`###` → 三级；`####` 会直接报错退出（规范只允许三级）
- `# 1 引言` 会自动改写为 `# 第1章 引言`；已写 `第1章` 的原样保留
- 摘/要、目/录这类两字标题建议用全角空格隔开（`摘　　要`），脚本对 `摘要`、`摘要 ` 等写法也能识别并自动补空格
- 一级标题除第一节外一律自动另起一页

## 3. 正文段落

一行一段（连续多行会合并成一段，中文不需要手动换行）。空行分段。

```markdown
药品的高效管理在药房的整个管理中发挥着至关重要的作用。传统的人工管理方式效率低下。

文中可用 **加粗** 强调，变量用 $Q_{safe}$，上标用 $m^{2}$。
```

- 正文自动：宋体小四、首行缩进 2 字符、1.5 倍行距、段前段后 0
- 行内公式：`$...$` 或 `$$...$$` 均可，内容按 Times New Roman 斜体排，支持 `_x`、`_{xx}`、`^x`、`^{xx}`

## 4. 列表（正文编号）

```markdown
本文的主要工作包括三个方面：

- 分析中小型药房的业务流程
- 完成系统总体架构与数据库设计
- 实现系统并完成测试
```

生成 `（1）（2）（3）`，首行缩进 2 字符、无悬挂缩进——符合"手动编号、最多两级"的要求。

需要二级编号时直接写进正文，脚本不会改动已带编号的段落：

```markdown
- 系统功能包括：
①药品管理；②库存管理；③销售管理。
```

## 5. 图

```markdown
系统整体架构如图2-1所示。

![图2-1 系统总体架构](fig/arch.png)
```

- 方括号里是图题，原样排在图片下方，宋体五号居中
- 路径相对稿件文件所在目录；图片等比缩放，默认最大宽 11 cm，可用 `--max-figure-cm` 调整
- 图片段落自动"与下段同页"，避免图与图题分家

## 6. 表

表题单独一行，紧跟管道表格，中间不留空行：

```markdown
各模块职责如表3-1所示。

表3-1 系统功能模块划分

| 模块名称 | 主要功能 | 使用角色 |
| --- | --- | --- |
| 药品管理 | 药品信息的增删改查 | 管理员 |
| 库存管理 | 入库、出库、库存预警 | 库管员 |
```

- 第一行为表头，表头下方自动加 0.5 磅细线，表格上下各 1.5 磅粗线，其余线全去掉
- 列宽按内容长度自动分配，整表占满版心
- 表后自动补一个空行段落（规范要求"表格与下文留一行空白"）

## 7. 公式

````markdown
预警判定条件如式（3-1）所示。

```formula (3-1)
Q_current < Q_safe
```

式中，$Q_{current}$ 为药品当前库存量，$Q_{safe}$ 为该药品的安全库存阈值。
````

- 块内可写多行，按原样居中排；括号里的编号会排到版面右侧
- 只做占位排版，复杂公式请用户在 Word 里用 MathType 或公式编辑器替换，保留 `(3-1)` 右对齐即可

## 8. 参考文献

```markdown
# 参考文献

[1] 吴功宜.计算机网络(第三版)[M].北京:清华大学出版社,2011:5-26.

[2] 符萌,郭进,王小敏等.铁路信号设备可靠性研究[J].中国铁路,2009,(12):56-59.
```

以 `[数字]` 开头的段落自动按参考文献条目排：宋体五号、左对齐、无首行缩进。

## 9. 代码（附录）

````markdown
```java
@RestController
public class DrugController {
}
```
````

等宽字体、单倍行距、无缩进。正文里不要贴大段代码，放附录。

## 10. 目录

不要在稿件里写目录条目。脚本会在第一个章标题前插入目录域，并设置"打开时自动更新"。
若稿件里已有 `# 目　　录` 标题，脚本会在该位置插入域并忽略后面的手写条目。

## 完整示例

见 `assets/sample-manuscript.md`，配套图片 `assets/fig_sample.png`。直接运行：

```bash
python scripts/build_thesis.py assets/sample-manuscript.md -o /tmp/demo.docx
```
